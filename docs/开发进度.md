  - `TradingDecisionWorker` 将 orderbook 事件 payload 传入入场计划。
  - entry replay 支持 fixture metadata，并在序列化结果中输出 metadata。
  - 新增应用层接线测试，确认直播状态 metadata 能从 app 入口进入策略门禁并回到 `EntryPlan.metadata`。
- 接通 sizing 阶段体育评估：
  - 当前焦点候选在预算分配前执行体育扫尾门禁。
  - 缺直播状态、评估拒绝或非自动执行权限会让当前候选 `buy_budget_usdc` 归零。
  - sizing metadata 与 entry decision metadata 使用同一套候选原因和执行权限字段。
- 接通候选审计投影：
  - `TradingDecisionWorker` 在 SKIPPED 和 RISK_CHECK 事件中输出 `plan_metadata`。
  - 缺少直播状态导致的候选拒绝会发布 SKIPPED 审计事件，便于后续管理台复盘。
  - SKIPPED 候选审计事件使用 P3 优先级，避免反向占用 P0 交易队列。
  - persistence 审计记录保留 outbox payload，避免落库后丢失 `plan_metadata`。
  - Admin 审计事件响应新增 `payload` 字段。
  - 前端审计页支持选中审计或 outbox 事件后查看 JSON 载荷。
- 新增通用入场 metadata provider 扩展点：
  - `TradingDecisionWorker` 支持在构建入场计划前合并外部 provider 返回的运行时事实。
  - provider 只补 metadata，不解析体育状态、不判断下单。
  - 测试确认 provider 字段会进入 `plan_metadata`，可作为后续直播比分状态接入点。
- 补充 entry replay 测试，确认 fixture metadata 能驱动体育扫尾计划并输出回放 metadata。
- 接通真实直播状态 store/provider：
  - 新增 `EntryMetadataStore`，按 `condition_id`、`market_slug` 或 `event_slug` 保存入场前运行时 metadata。
  - `build_runtime()` 装配 `EntryMetadataStore`，并把它接入 `TradingDecisionWorker.entry_metadata_provider`。
  - provider 只读取内存状态并返回 metadata，不解析体育规则、不做下单判断。
- 接通候选展示与人工确认入口：
  - AdminService 新增直播状态写入/查询、体育扫尾候选投影和候选人工确认。
  - 新增 `/candidates`、`/candidates/live-states`、`/candidates/confirm` API。
  - `manual_confirm` 候选在人工确认后重新构建入场计划，并继续经过 `TradingService -> RiskManager -> OrderExecutor`。
  - 前端新增 `/candidates` 页面，展示候选、直播状态和人工确认结果；确认按钮只依赖服务端 `confirmable`。
- 补充人工确认测试，确认 Moneyline 候选不会自动下单，但带确认 metadata 后可生成 BUY intent 并经过风控执行。

### 当前决策

- 后续实现必须同时考虑 `sports_tail` 纯业务模型、配置、universe、outcome 解析、trading 接入、recovery 和管理展示，不按单个测试最小闭合。
- 三类盘口必须共享候选和评估模型。
- 代码实现前可以先不写测试；测试用于验证目标实现，不倒逼局部最小实现。
- 当前不改 `ExtensionDecision`、`ExtensionHooks`、`TradingService`、`RiskManager` 和 `OrderExecutor`；`TradingDecisionService` 只做 metadata 透传，不加入体育策略判断。
- 候选展示走服务端候选投影和 audit payload；候选级拒绝原因不写入 `Market.reject_reason`。
- 自动下单前必须能从 `ExtensionContext.metadata` 读取直播比赛状态；缺失时返回 `missing_live_game_state`，不会创建 BUY。
- 通用 app 层只负责透传和审计 metadata，不复制体育策略判断。
- 直播状态输入应通过通用 metadata provider/enricher 在入场前补全，框架只透传，不解析体育状态。
- 人工确认入口不是交易客户端直连入口，必须重新构建入场计划并通过 TradingService、RiskManager 和 OrderExecutor。
