# 体育类扫尾自动交易业务需求

## 1. 目标

构建一个“电脑交易助手”，替代人工金融分析师持续观察 Polymarket 体育直播页面，只捕捉比赛末段或结果已经高度确定时，市场价格尚未完全反映的扫尾机会。

本需求只描述业务操作和盈利策略，不约束具体技术实现。

## 2. 核心盈利逻辑

策略不以预测整场比赛为目标，而是等待比赛接近结束、结果已经较清晰时再行动。

主要盈利来源：

- 体育直播盘口数量多，人工难以及时覆盖所有比赛。
- 比分或比赛状态变化后，部分挂单没有及时撤销。
- 市场价格短时间内滞后于比赛事实。
- 接近结算的正确结果仍可能以低于 100¢ 的价格成交。

单笔收益来自：

```text
结算价值 100¢ - 买入价格 - 交易成本 - 滑点
```

因此本策略追求高胜率、小利润、严格筛选，不追求大赔率。

## 3. 策略一：总分已打穿扫尾

这是最清晰、确定性最高的扫尾策略，应作为默认启用策略。

操作逻辑：

- 只看直播中的 `总分 / Totals` 盘口。
- 读取当前比分，计算两队当前总分。
- 如果当前总分已经超过某个 Over 盘口线，则 Over 结果已经事实成立。
- 如果当前总分已经使某个 Under 盘口在剩余时间内接近不可能被打穿，则可作为低优先候选。
- 优先买入已经事实成立的 Over，不优先做仍依赖剩余时间推演的 Under。

示例：

```text
当前比分：3-2
当前总分：5
盘口：Over 4.5
Over 价格：98¢
```

在此场景下，Over 4.5 已经成立。若规则无异常、价格仍低于目标价、流动性足够，可以买入。

不交易场景：

- 价格已经接近 100¢，收益不足。
- 比赛状态异常，例如暂停、延期、取消、比分争议。
- 页面比分与盘口含义无法确认。
- 盘口规则存在特殊结算条件。
- 买入深度不足，实际成交价格过高。

## 4. 策略二：比赛末段领先方扫尾

该策略属于完整目标能力的一部分。当前运行目标要求进入自动执行权限，但必须继续经过价格、流动性、仓位、账户和订单执行门禁。

适用场景：

- NBA 第四节最后几分钟，领先优势明显。
- NHL 第三节最后几分钟，领先方仍有折价。
- 足球 80 分钟后，领先 2 球以上。
- 网球接近赛点或局盘优势极大。

操作逻辑：

- 只看比赛最后阶段。
- 判断领先方是否已经具备极高胜率。
- 如果领先方价格明显低于分析师判断的真实胜率，才考虑买入。
- 小比分领先、时间仍多、存在加时或特殊规则时跳过。

主要风险：

- 足球补时、红牌、点球。
- NBA 末段犯规战术。
- NHL 空门、加时和点球。
- 网球退赛或伤病。

## 5. 策略三：让分盘口扫尾

让分盘口风险高于总分和胜负线，但应在整体业务设计中一次性纳入，避免未来以补丁方式追加。

操作逻辑：

- 不做比赛早中期让分。
- 只在比赛末段判断让分结果是否接近锁定。
- 剩余时间、领先差距和盘口线必须形成明显安全垫。
- 如果最后阶段垃圾时间得分仍可能改变让分结果，则跳过。

## 6. 电脑操作流程

每日运行后，电脑助手应按以下业务流程工作：

1. 打开体育直播市场。
2. 只关注标记为直播中的比赛。
3. 按优先级扫描 `Totals`、`Moneyline`、`Spreads`。
4. 先找总分已经事实成立的盘口。
5. 对候选盘口检查当前价格、交易量、可成交深度和比赛状态。
6. 满足条件时执行小额买入，或在人工确认模式下发出提醒。
7. 买入后持续观察价格和比赛状态。
8. 默认不自动挂卖单，等待权威结算。
9. 如果显式开启自动退出或人工操作，价格快速回归到接近 100¢ 时允许提前卖出锁定利润。
10. 若状态异常、比分不一致、盘口关闭或流动性消失，停止加仓并提示人工处理。

## 7. 入场条件

所有自动交易必须同时满足以下条件：

- 比赛处于直播状态。
- 盘口类型在白名单内。
- 当前结果已经事实成立，或胜率极高。
- 买入价格低于设定上限。
- 预期收益覆盖交易成本和滑点。
- 市场有足够成交深度。
- 比分和比赛阶段信息清晰、及时。
- 没有暂停、延期、取消、争议或规则不明状态。
- 单场、单日、单盘口风险额度未超限。

## 8. 禁止交易条件

出现以下任一情况时必须跳过：

- 未开赛比赛。
- 价格接近 100¢，剩余利润过薄。
- 流动性太差，无法按目标价格成交。
- 比分刚变化但盘口仍剧烈波动。
- 页面比分、盘口名称或结算含义不清楚。
- 比赛状态为暂停、延期、取消、争议、退赛。
- 看不懂规则的盘口。
- 板球、电竞、球员数据等复杂盘口，除非已经纳入明确的策略白名单和规则校验。
- 当天已达到亏损上限。

## 9. 资金与风控

资金管理原则：

- 单笔小额，不一次性打满。
- 单场比赛设置最大投入。
- 单个联赛设置最大投入。
- 同一比赛多个盘口不能重复暴露同一风险。
- 连续亏损后自动暂停。
- 当天达到最大亏损线后停止交易。
- 新策略先使用提醒模式或极小金额验证。

退出原则：

- 默认等待结算，不自动挂 follow-up SELL。
- 显式开启自动退出或人工操作时，价格达到目标卖出价可提前卖出。
- 状态异常时停止加仓，必要时减仓或退出。
- 出现数据不一致时，优先保护本金。

## 10. 目标需求范围

目标业务能力覆盖**整个体育市场**的扫尾机会，按盘口家族分层：

**直播比分驱动**（`single_game` 家族，已具备实时比分源 → 全部自动执行权限）：

- 总分已打穿或接近锁定的 `Totals` 机会。
- 比赛末段领先方价格仍有折价的 `Moneyline` 机会。
- 比赛末段让分结果接近锁定的 `Spreads` 机会。

**长周期市场**（`outright` / `season` 家族，依赖赛季 / 系列赛状态而非单场比分；当前以
record-only / 人工确认权限为主，逐步纳入自动执行）：

- 系列赛冠军、赛季归属、分组出线等 outright 市场。
- 球员转会、奖项归属等长期市场。
- 板球（cricket）等具备结构化赛季状态源、可由 `season_state` 系统建模的市场。

三类家族共用同一套候选、评估、风控和退出框架——按家族注入不同的定价模型、live source
和执行权限；策略可按盘口配置降级为提醒或人工确认。详见 `src/strategies/current/` 内
`tail_*` 与 `outright_*` 配置族。

**仍明确不做**：

- 基于新闻、伤病、舆情做主动预测。
- 无任何结构化数据源、规则不可形式化的电竞 / 球员极端 prop 盘口（缺胜率判断 + 风控
  闭环条件）。

新发现的市场不得因缺专用模型而长期静默忽略：未具备自动执行条件的家族至少要纳入候选
诊断、给出可审计拒绝或 record-only 原因（CLAUDE.md §9）。

## 11. 验收标准

业务验收以金融分析师可理解的操作结果为准：

- 能列出当前直播体育中的候选扫尾机会。
- 每个候选机会必须显示比赛、盘口、当前比分、盘口线、价格和判断理由。
- 能明确说明为什么买入或为什么跳过。
- 所有策略使用同一套候选、评估、风控和退出口径。
- 不同策略可以配置不同执行权限：只提醒、人工确认、自动执行。
- 默认自动执行对象覆盖 Totals、Moneyline 和 Spreads 三类扫尾机会。
- 每笔交易前必须显示预估收益和最大亏损。
- 每笔交易后必须记录买入价格、退出价格、结果和盈亏。
- 出现异常状态时必须停止自动买入。

## 12. 总结

本策略的本质是体育直播扫尾交易，不是赛前预测，也不是高赔率下注。

目标设计应一次性覆盖总分、胜负线和让分三类扫尾策略，统一候选识别、入场判断、风控、退出和审计口径。实际交易权限可以分层开放，但业务模型不应为单个策略临时追加旁路。
