# 系统工作流

## 0. 心智模型

整个 polymarket_trader 后端 = **1 个 `TradingWorkflow` 实例 + 围绕它的 runtime 基础设施**。
没有"策略"层、没有"策略选择"——就是一个量化交易工作流。

工作流内嵌的决策器是 `QuantDecider`。所有 BUY / SELL / cancel / replace
意图都从它出来。`QuantTriggerKind` 枚举本身就只有 2 个值，这是代码层
事实：

```python
class QuantTriggerKind(StrEnum):
    MARKET_TICK = "market_tick"          # 工作流 1
    RECONCILE_CYCLE = "reconcile_cycle"  # 工作流 2
```

所以系统有**2 条决策工作流 + 1 条反馈链路 + N 条喂料链路**。
喂料链路只写内存 store，不触发决策；决策只在 market_tick 和
reconcile_cycle 上发生。

---

## 1. 工作流 1：market_tick（入场 + 持仓动作）

这是主决策路径。入场（BUY）和持仓动作（SELL / replace / cancel）**都在同一
决策入口**，按"是否已有持仓"分派——不存在独立的"入场决策"链路。

### 1.1 触发源

| 触发 | 来源 | 周期 / 条件 |
|---|---|---|
| ORDERBOOK_SNAPSHOT_UPDATED | market_ws WS push（book / price_change） | 实时（市场活跃时每秒多次） |
| 同上（合成） | position_exit_evaluator scheduler job | 5s（薄盘场景兜底，每个持仓 token 合成一条） |
| ENTRY_SIGNAL_TRIGGERED | SportsLiveStateWorker（直播状态变更时） | live state 刷新时（demand-driven） |

### 1.2 决策路径

```
TradingDecisionWorker (P0 worker)
    ↓
DecisionContextBuilder.build_entry_plan
    ↓ 构造 DecisionContext(trigger=market_tick, ...)
TradingWorkflow.quant_decide(context)
    ↓
QuantDecider._decide_market_tick(context)
    ├─ 有持仓  → _decide_position_action  → SELL / replace / cancel
    └─ 无持仓  → _decide_entry_attempt    → BUY（含 Kelly sizing）
    ↓ TradingDecision
OrderGateway → RiskManager → OrderExecutor → Polymarket CLOB
```

### 1.3 入场决策内部门禁（在 QuantDecider 里完成）

入场门禁**全部内嵌在决策器内部**，按层依次：

1. universe 门禁 — `TradingWorkflow.select_market` 在 discovery 阶段就已过滤
2. market family 路由 — `_decide_entry_attempt` 按 SINGLE_GAME / OUTRIGHT / SERIES / ESPORTS 分派
3. Kelly sizing — 价格上限 / 流动性 / min edge / per-market cap / drawdown halt
4. capital efficiency gate — 预期毛利 / 资金占用时长
5. 现金硬下限 — context.available_usdc < $5 直接 skip

通过所有门禁 → 产出 BUY `TradingDecision` + `position_plan` metadata。

## 2. 工作流 2：reconcile_cycle（周期兜底 / 恢复）

```
periodic_reconcile scheduler job (20s)
    ↓
ReconcileWorker → ReconcileService.build_market_plan
    ↓ 构造 DecisionContext(trigger=reconcile_cycle, ...)
TradingWorkflow.quant_decide(context)
    ↓
QuantDecider._decide_reconcile (recovery 子流程)
    ↓ recovery actions
ReconcileActionApplier → OrderExecutor
```

职责：
- 清僵尸订单（chain 上还在但 store 里没记的 open order）
- 补漏挂的 SELL（高成本仓位漏挂 profit-take）
- 全局降级 pause（直播源全断时主动暂停所有 single_game 入场）
- 与工作流 1 共享同一个 `QuantDecider` 实例，但走 `reconcile_cycle` 分支

---

## 3. 反馈链路（不触发决策）

```
Polymarket user_ws (订单 / 成交 / 持仓变更推送)
    ↓
UserWsWorker → AccountStateProjector
    ↓
AccountStateStore（内存）
    ↑
下次 market_tick 时 quant_decide 自然读到新持仓
```

**为什么 user_ws 不触发决策**：fill 是过去决策的结果，下一次 market tick
时量化器自然读最新 `AccountSnapshot` 决策。让 user_ws 触发决策反而会
和 market_tick 抢锁、做重复评估。

`paper_balance_syncer`（paper 模式）每秒把 paper_ledger 投影回
account_state_store，是反馈链路的虚拟版本，原理一致。

---

## 4. 喂料层

喂料链路一直在跑，**只往内存 store 写数据，不直接触发决策**。决策发生
在工作流 1/2，那时从 store 读最新值。

| Worker / Job | 数据源 | 写入 store | 周期 |
|---|---|---|---|
| DiscoveryRunner | Gamma `/events?live=true` | MarketRegistry + GammaMarketSnapshotStore | 2s |
| MarketWsWorker | Polymarket market_ws | OrderbookDeltaStore + OrderbookHistoryBuffer + OrderbookDerivedStore | 实时 |
| SportsLiveStateWorker | Goalserve inplay + livescore | MarketMetadataStore（live state） | demand-driven 1s+ |
| SportsSeasonOddsWorker | TheOddsAPI 赛季赔率 | MarketMetadataStore（season odds） | 周期 |
| GameOddsWorker | TheOddsAPI 单场赔率 | MarketMetadataStore（game odds） | 周期 |
| GoalservePregameWorker | Goalserve 赛前赔率 | MarketMetadataStore（pregame） | 启用时周期 |
| UserAccountPoller | data-api positions / clob balance | AccountStateStore | 20s（market_sync_interval_seconds） |

注意 `DiscoveryRunner` 在写 `MarketRegistry` 时会调
`MarketIngestService.select_market` → `TradingWorkflow.select_market`，
**universe 精筛是 discovery 链路的一部分**，不是入场决策的一部分。
决策器拿到的市场已经过 universe 门禁。

## 5. 状态真相源（CLAUDE.md §3 不可违反）

| 优先级 | 来源 | 用途 |
|---|---|---|
| 1 | Polymarket 实时事件 + 权威快照 | 决策真相 |
| 2 | 内存 stores（AccountState / MarketRegistry / MarketMetadata / Orderbook*） | P0 热路径读取 |
| 3 | PostgreSQL | **仅审计**，不参与运行时决策 |

DB 异步落库走 outbox → PersistenceWorker，**绝不反向阻塞决策路径**。

## 6. Runtime 装配（main.py `build_runtime`）

```
基础设施
  ├─ Polymarket clients (Gamma / Clob / Data / WS)
  ├─ Goalserve clients (inplay / livescore / pregame / lazy)
  ├─ ThreadPools (trading / maintenance / process)
  └─ Settings + LoggingRuntime + MetricsRegistry

内存 stores
  ├─ MarketRegistry / GammaMarketSnapshotStore
  ├─ AccountStateStore / MarketMetadataStore
  ├─ OrderbookDeltaStore / OrderbookHistoryBuffer / OrderbookDerivedStore
  └─ SeasonStateStore

TradingWorkflow
  └─ TradingWorkflow(config=TradingWorkflowConfig, ports=RuntimePorts)
      └─ 内部装配 QuantDecider

Services
  ├─ MarketIngestService (discovery 用)
  ├─ DecisionContextBuilder (工作流 1 入口)
  ├─ ReconcileService (工作流 2 入口)
  └─ OrderGateway + RiskManager + OrderExecutor

Workers (长驻 P0/P2 task)
  ├─ MarketWsWorker / UserWsWorker (P0)
  ├─ TradingDecisionWorker (P0)
  ├─ ReconcileWorker (P2)
  ├─ PersistenceWorker (P3, audit only)
  ├─ MarketDiscoveryWorker (P2)
  └─ SportsLiveStateWorker / Season/Game/Pregame OddsWorker (P2)

Paper 模式（settings.paper_trading_mode=true 时）
  └─ build_paper_runtime → PaperVirtualLedger + 4 个 background task

Scheduler + Supervisor + EventBus + LifecycleBus 收尾
```

## 7. 模块职责映射

| 目录 | 在工作流中的角色 |
|---|---|
| `quant/workflow.py` | TradingWorkflow 主类 — 工作流 1/2 的决策入口 |
| `quant/quant_decider.py` | QuantDecider — 所有 BUY/SELL/cancel/replace 的唯一决策器 |
| `quant/{tail,outright,series}/` | 各 market family 的子决策模块 |
| `quant/allocation.py` + `quant/trading/` | Kelly sizing / gate / exit overlay 辅助 |
| `domain/` | 纯 DTO（Order / Position / Fill / Market / DecisionContext / TradingDecision） |
| `app/` | 用例编排：DecisionContextBuilder（工作流 1） / ReconcileService（工作流 2） / MarketIngestService（discovery） / AdminService（人工操作） |
| `infra/polymarket/` | CLOB / Gamma / Data / WS / OrderExecutor 客户端 |
| `infra/sports/` | Goalserve inplay / livescore / pregame 客户端 |
| `infra/db/` | SQLAlchemy models + repositories（**只审计**） |

## 8. 常见误解

| 误解 | 实际 |
|---|---|
| "discovery 是入场链路的一部分" | discovery 是**喂料**，universe 门禁在这层完成；入场决策在 QuantDecider 里发生 |
| "ENTRY_SIGNAL_TRIGGERED 是独立的入场决策链路" | 它只是 market_tick 的一种触发源，最终走同一个 `_decide_market_tick` |
| "BUY 和 SELL 在不同链路" | 都在 `_decide_market_tick`，按"有/无持仓"分派 |
| "user_ws fill 会触发决策" | user_ws 只更新账户状态；下次 market_tick 自然读到新持仓 |
| "reconcile 是异常恢复" | reconcile 是**周期兜底**——清僵尸单 / 补漏挂单 / 全局降级 pause 都在这里 |
| "策略和工作流是两层" | 没有"策略"概念，整个系统就是一个 TradingWorkflow |
