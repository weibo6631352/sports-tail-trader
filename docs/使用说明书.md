# 使用说明书

本文面向日常操作者，说明如何启动、观察、人工确认和排障。
策略设计、接口字段和开发规则分别看 [业务需求](./业务需求.md)、[api.md](./api.md)、[设计文档](./设计文档.md) 和 [AGENTS.md](../AGENTS.md)。

## 1. 启动前确认

先确认仓库根目录存在 `.env`，至少应检查这些内容：

- 钱包和 Polymarket API 凭据是否按当前账户填写。
- `PORTFOLIO_BUDGET_USDC`、`MAX_ORDER_USDC`、`MAX_MARKET_USDC`、`MAX_TOTAL_USDC` 是否符合本次运行预算。
- `MAX_OPEN_ORDERS` 是否大于 0。
- `EXTENSION_MODULE` 是否指向当前策略，默认是 `strategies.current`。
- 如启用体育直播状态源，确认 `SPORTS_LIVE_STATE_ENABLED=true`、`SPORTS_LIVE_STATE_SOURCES=espn,nba,nhl,mlb,sofascore,thesportsdb`、`SPORTS_LIVE_STATE_LEAGUES` 已填写。

不要把私钥、API secret 或生产数据库密码提交到仓库。

## 2. 启动和停止

在仓库根目录执行：

```bash
./start_all.sh
```

启动脚本会做这些事：

- 准备 Python 运行环境。
- 加载 `config/.env` 和 `.env`。
- 初始化数据库 schema。
- 如默认 PostgreSQL 不可用，尝试拉起仓库内本地 PostgreSQL。
- 构建前端静态资源。
- 启动后端和前端。
- 尝试打开浏览器。

默认地址：

- 前端管理台：`http://127.0.0.1:5173/`
- 后端 API：`http://127.0.0.1:8000`
- 后端接口文档：`http://127.0.0.1:8000/docs`

停止：

```bash
./stop_all.sh
```

如果代码刚更新但页面行为没变，先重启：

```bash
./stop_all.sh
./start_all.sh
```

## 3. 运行状态判断

打开前端后，先看顶部状态和“总览”页。

重点看：

- 当前阶段是否进入交易启用态。
- 是否显示“自动交易已就绪”。
- `blocking_reasons` 是否为空。
- 用户 WS 是否连接。
- 最近 reconcile 时间是否刷新。
- 市场数量是否在增长或保持正常。
- outbox 深度是否持续堆积。

常用 API 快速检查：

```bash
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/ready
curl -s http://127.0.0.1:8000/runtime
```

`/runtime` 只给运行态样本和计数。完整市场列表要看 `/markets` 或前端“市场”页。

## 4. 页面说明

### 总览

用于判断系统整体是否能交易。

看这些信息：

- 自动交易是否就绪。
- 账户、余额、授权额度。
- 市场跟踪数量。
- 最近扫描和同步状态。
- worker、队列、持久化状态。

### 市场

用于查看当前跟踪市场。

操作建议：

- 用搜索和筛选定位 market。
- 查看盘口、手续费、中间价和价格历史。
- 价格历史偶发较慢时，先看其他页面是否仍正常；它一般不代表交易主链路阻塞。
- 完整市场分页由 `/markets` 提供，不从 `/runtime` 读取全量市场。

### 候选

用于查看体育扫尾策略候选。

候选页只展示后台已经形成的运行时事实，不触发全市场临时策略评估。

操作建议：

- 先按盘口类型、比赛状态、动作、执行权限筛选。
- 只在 `confirmable=true` 且原因、盘口、比分状态都符合预期时人工确认。
- 人工确认后，系统仍会经过 allocator、risk manager、trading service 和 order executor。
- 候选为空不代表后台停止，只表示当前没有可展示候选。

### 订单

用于查看订单状态和执行受控操作。

操作建议：

- 重点看 open order。
- 买入侧不应长期保留 resting BUY order。
- 如发现异常 resting order，优先走系统提供的取消、替换或 reconcile 流程，不直接绕过后端操作交易客户端。

### 持仓

用于查看当前 position、fills 和账户暴露。

操作建议：

- 核对 shares、成本、当前价值和可赎回状态。
- 和 Polymarket 页面或导出数据不一致时，先跑 reconcile，再看复盘页。

### 复盘

用于核对真实成交、订单、持仓、审计上下文和策略候选上下文。

操作建议：

- 按 `condition_id`、`token_id` 或市场关键词筛选。
- 成交后再用这里核对盈亏口径。
- 如果要和 Polymarket 页面/导出数据对账，保留导出文件和对应时间点。

### 审计

用于查看审计事件和待处理 outbox。

操作建议：

- outbox 深度持续增长时，优先排查数据库、持久化 worker 和网络。
- 市场发现、盘口快照、候选拒绝和扫描状态不应大量写入数据库 outbox。
- 订单、成交、持仓、余额等交易快照才是主要持久化对象。

### 操作

用于人工 reconcile、预算分配或其它受控操作。

操作建议：

- 只在明确需要修正账户、订单或持仓状态时执行。
- 执行前记录当前问题和目标。
- 执行后回到总览、订单、持仓、审计页确认结果。

## 5. 人工确认候选流程

建议顺序：

1. 在“候选”页筛选 `confirmable=true`。
2. 查看比赛状态、剩余时间、盘口类型、方向、best ask、风险原因和退出计划。
3. 打开对应 Polymarket 页面或外部比分源做人工核对。
4. 确认账户余额、授权额度和仓位暴露正常。
5. 点击确认入口。
6. 到“订单”页看订单状态。
7. 到“持仓”和“复盘”页核对成交和后续状态。

不要因为候选存在就默认下单。候选只是策略输出的受控操作对象，最终是否执行仍取决于风控和执行结果。

## 6. 数据和性能边界

运行时真相优先级：

1. Polymarket 实时事件与权威快照。
2. 本地内存状态。
3. PostgreSQL 审计与快照。

使用时注意：

- 数据库不是交易唯一真相。
- 前端查询不能决定后台业务是否继续运行。
- 后台市场发现、WS 订阅和交易判断不因前台页面展示而停止。
- 已结束且无持仓、无 pending buy、无 open order 的市场不会新增订阅，已有订阅会在 reconcile 后退出 registry 和 WS 跟踪。
- 若已结束市场仍有持仓或挂单，系统会继续保留跟踪，直到风险敞口清空。
- 同一 token 的高频未消费盘口事件会在队列边界合并为最新事实，交易 worker 不按时间静默丢已出队事件。
- `/runtime` 返回 `market_sample` 和 `registry.market_count`，不是完整市场列表。
- 完整市场列表使用 `/markets`。

## 7. 常见问题

### 页面打不开

检查服务是否监听：

```bash
ss -ltnp | rg ':(8000|5173)\b'
```

如果没有监听，重新启动：

```bash
./start_all.sh
```

### 页面显示未就绪

先看：

```bash
curl -s http://127.0.0.1:8000/ready
```

常见原因：

- 私钥或 API 凭据缺失。
- 预算或订单上限为 0。
- 用户 WS 未连接。
- reconcile 未完成或不新鲜。
- 体育直播状态源配置错误。

### 候选一直为空

按顺序看：

- 市场页是否有跟踪市场。
- `/runtime` 的 `sports_live_sync` 是否有最近成功，并检查 `source_statuses` 中 ESPN/NBA/NHL/MLB/SofaScore/TheSportsDB 哪个源失败或返回 0 场。
- 候选页筛选条件是否过窄。
- 策略参数是否过严。
- 当前比赛是否真的进入扫尾窗口。

### 页面卡顿或请求慢

先区分慢在哪里：

- 候选、runtime、markets 是否都慢。
- 是否只有 `prices-history` 慢。
- 浏览器 console 是否有 5xx。
- outbox 深度是否增长。
- 后端 CPU 是否持续异常。

基础检查：

```bash
curl -s -w '\n%{http_code} %{time_total}\n' http://127.0.0.1:8000/runtime
curl -s -w '\n%{http_code} %{time_total}\n' 'http://127.0.0.1:8000/candidates?limit=50&offset=0'
curl -s -w '\n%{http_code} %{time_total}\n' 'http://127.0.0.1:8000/markets?limit=50&offset=0'
```

### 修改代码后页面没变

前端静态资源和后端进程需要重启：

```bash
./stop_all.sh
./start_all.sh
```

### 数据库异常

先看启动日志：

```bash
cat .dev-runtime/database-init.log
cat .dev-runtime/postgres/postgres.log
```

开发环境 schema 结构变更时，以当前目标模型为准，重建开发库后重新初始化。

## 8. 日常验收命令

提交前建议跑：

```bash
pytest -q
ruff check .
npm --prefix frontend run typecheck
npm --prefix frontend run lint
VITE_API_BASE_URL=/api npm --prefix frontend run build
```

真实页面验收：

- 打开 `http://127.0.0.1:5173/`。
- 依次查看总览、市场、候选、订单、持仓、复盘、审计、操作。
- 确认浏览器 console 没有新的 error。
- 确认 `/runtime`、`/markets`、`/candidates` 返回 200。
