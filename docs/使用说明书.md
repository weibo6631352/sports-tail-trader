# 使用说明书

面向日常操作者，说明启动、观察、人工确认和排障。配置看 [config.md](./config.md)，开发规则看 [CLAUDE.md](../CLAUDE.md)。

## 1. 启动前确认

仓库根 `.env` 至少检查：

- 钱包和 Polymarket API 凭据。
- `PORTFOLIO_BUDGET_USDC > 0`（bankroll 软上限）。
- 策略参数（Kelly κ / 阈值 / 各 family 预算）在仓库根 `strategy_config.toml`，启动期自动加载。
- 启用直播状态源时 `GOALSERVE_API_KEY` 非空，`SPORTS_LIVE_STATE_LEAGUES` 按需配置。

私钥 / API secret / 生产数据库密码绝不入仓。

## 2. 启动与停止

仓库根：

```bash
./start_all.sh    # 启动后端 + 前端 + 必要时本地 PG
./stop_all.sh     # 停止
```

默认地址：

- 前端：`http://127.0.0.1:5173/`
- 后端：`http://127.0.0.1:8000`
- 接口文档：`http://127.0.0.1:8000/docs`

代码改了页面没变 → 重启。

## 3. 运行状态判断

打开前端后看顶部状态和"总览"页：

- 自动交易是否就绪、`blocking_reasons` 是否空。
- 用户 WS 是否连接、最近 reconcile 时间是否刷新。
- 市场跟踪数量是否正常、outbox 是否在堆积。

快速检查：

```bash
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/ready
curl -s http://127.0.0.1:8000/runtime
```

`/runtime` 只给样本和计数；完整市场列表走 `/markets`。

## 4. 页面说明

- **总览**：自动交易就绪状态、账户余额/授权、worker 与队列健康。
- **市场**：当前跟踪市场，可搜索、查盘口、查价格历史。完整分页由 `/markets` 提供。
- **候选**：策略候选实时快照。`confirmable=true` 且原因/盘口/比分符合预期才人工确认。确认后仍走 entry planner → risk → executor 全链路。直播源覆盖排查走 `GET /candidates/live-source-gaps`。
- **订单**：订单状态 + 受控操作。重点看 open order；买入侧不应长期保留 resting BUY。异常 resting order 优先走系统取消/替换/reconcile，不绕后端。
- **持仓**：当前 position、fills、账户暴露。对账不一致先跑 reconcile。
- **复盘**：核对真实成交、订单、持仓、审计上下文。按 condition_id / token_id / 市场关键词筛选。
- **审计**：审计事件 + 待处理 outbox。outbox 持续增长 → 排查 DB / persistence worker / 网络。
- **操作**：人工 reconcile、预算分配等受控操作。执行前记录目标，执行后回总览/订单/持仓/审计核对。
- **虚拟盘**：用当前真实数据跑一次主链路验收。`sign` 是真实签名，`submit` 是虚拟。先看"机会漏斗"定位掉在哪一层，再看"拒绝原因聚合"。返回 `no_trade` 说明当前真实数据无满足自动执行的候选，不是页面故障。

## 5. 人工确认流程

1. 候选页筛 `confirmable=true`。
2. 查比赛状态、剩余时间、盘口类型、方向、best ask、风险原因、退出计划。
3. 必要时打开 Polymarket 页面或外部比分源核对。
4. 确认账户余额、授权额度、仓位暴露正常。
5. 点击确认。
6. 到订单 / 持仓 / 复盘页核对结果。

候选存在不等于必须下单——最终是否执行仍由风控和执行结果决定。

## 6. 数据真相优先级

1. Polymarket 实时事件与权威快照。
2. 本地内存状态。
3. PostgreSQL（仅审计，不参与运行时决策）。

- 已结束且无持仓 / 无 pending / 无 open order 的市场会在 reconcile 后退出跟踪。
- 已结束但仍有暴露的市场保留跟踪直到敞口清空。
- 同 token 高频盘口事件在队列边界合并为最新事实。

## 7. 常见问题

**页面打不开**：`ss -ltnp | rg ':(8000|5173)\b'` 没监听就 `./start_all.sh`。

**未就绪**：`curl -s http://127.0.0.1:8000/ready` 看 blocking 原因。常见：私钥/凭据缺失、预算 0、user WS 未连、reconcile 不新鲜、直播源配置错。

**候选一直为空**：依次排查
- 市场页有无跟踪市场。
- `/runtime` 的 `sports_live_sync` 最近成功，Goalserve inplay/livescore 哪个 sport 失败。
- 候选页筛选是否过窄。
- 策略门禁是否过严：`GET /analytics/risk-rejections/aggregate` 看哪条规则在拒、`GET /analytics/edge-realization` 看当前 edge 门槛样本量。临时放宽走 `PUT /parameters/{scope}/{key}`（详见 [config.md](./config.md) 运行时调参节）。
- 当前比赛是否真的进入策略窗口。

**请求慢**：

```bash
curl -s -w '\n%{http_code} %{time_total}\n' http://127.0.0.1:8000/runtime
curl -s -w '\n%{http_code} %{time_total}\n' 'http://127.0.0.1:8000/candidates?limit=50&offset=0'
curl -s -w '\n%{http_code} %{time_total}\n' 'http://127.0.0.1:8000/markets?limit=50&offset=0'
```

区分慢在哪一个端点；只有 `prices-history` 慢一般不阻塞主链路。

**改完代码页面没变**：`./stop_all.sh && ./start_all.sh`。

**数据库异常**：先看 `.dev-runtime/database-init.log` 和 `.dev-runtime/postgres/postgres.log`。schema 变更直接重建开发库（CLAUDE.md §8 不写迁移代码）。

## 8. 日常验收

提交前：

```bash
ruff check .
npm --prefix frontend run typecheck
npm --prefix frontend run lint
VITE_API_BASE_URL=/api npm --prefix frontend run build
```

页面验收：打开 `http://127.0.0.1:5173/`，依次过总览/市场/候选/订单/持仓/复盘/审计/操作，确认 console 无新 error，`/runtime` / `/markets` / `/candidates` 返回 200。
